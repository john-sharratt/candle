# BDP Provenance Calibration — 2026-05-16

## Overview

Calibration of the MH_XOR_QQ_l0xl4 binary-directional-provenance (BDP) retrieval signal for all
eight projection layers.  Strategy locked: `ScoreFormula::Span { alpha: 2.0 }` over three depth
bands.  Goal: per-layer depth weights that maximise retrieval accuracy and a conservative score
threshold that limits false positives.

### What "depth bands" are

The BDP scanner captures sign-bit XOR signatures at three attention-depth levels, sampled at layer
pairs (l0, l4) within each band:

| Band | Attention depth | Captures |
|------|----------------|---------|
| **syntactic** | shallowest pair | token-level patterns, code idioms, structural syntax |
| **semantic** | mid pair | phrase-level co-occurrence, concept clusters |
| **pragmatic** | deepest pair | discourse-level context, intent, topic coherence |

`DepthWeights { syntactic, semantic, pragmatic }` is a weighted sum of the three band scores,
normalised by their total so only the ratios matter.

**Phase 1 key finding**: 5 of 8 layers have ratio < 1.0 (mean_intra < mean_inter).  The 8-item
within-layer corpus is too homogeneous — probes and corpus items discuss the same files in similar
ways, giving insufficient cross-item contrast.  Only `static_analysis` shows strong within-layer
discrimination (ratio 3.4×); the rest cannot be reliably calibrated from within-layer data alone.

## Phase 2 — Cross-corpus sweep

**Test**: `cross_corpus_provenance_sweep`
**Corpus per probe**: all 64 items from all 8 layers pooled (8-layer × 8-item combined list).
**Probes**: 640 (all positive + boundary scenarios).
**Metric**: MRR (1/rank) and Top-1 accuracy; correct item must be ranked #1 out of 64.
**Weight configs**: 91 distinct normalised combinations, generated by deduplicating the
`{0,1,2,3,4}^3` integer grid by normalised value.

The larger, cross-type corpus provides the contrast that Phase 1 lacked: different content types
produce visually distinct BDP signatures, making per-layer discrimination measurable.

## Observations

### Phase 1 gave inverted signal for 5 of 8 layers

Within a single 8-item layer, all probes and corpus items discuss the same source files in
similar ways.  The BDP scanner sees topically identical content and cannot discriminate.
The apparent inversion (mean_intra < mean_inter) is an artefact of the small homogeneous corpus:
the few corpus entries for the probe's own item happen to be less representative than the mass of
entries from the 7 other items.

### Phase 2 reveals the true signal

Pooling all 64 items makes content-type differences visible.  A code reading probe looks nothing
like a dream log entry at the BDP level, providing the contrast needed to rank the correct item
first.  This is exactly how the system will operate in production: the combined KV corpus spans
all content types.

### Why each layer uses its specific bands

| Layer | Band | Reason |
|-------|------|--------|
| bug_analysis (syn, 100%) | syntactic | Error-check idioms and boundary patterns are highly idiomatic at the token level; perfectly distinctive |
| architectural_analysis (syn+sem, 100%) | syntactic + semantic | Architectural prose references structure and naming; syntactic identifies the file, semantic anchors the concept |
| code_reading (sem+prag, 100%) | semantic + pragmatic | Raw code activates mid-to-deep attention patterns; syntactic alone conflates overlapping scopes |
| dependency_analysis (syn+prag, 94%) | syntactic + pragmatic | Import patterns are syntactic; pragmatic captures cross-file coupling intent |
| daily_history (syn+sem, 96%) | syntactic + semantic | Developer log vocabulary is semantic; syntactic prevents cross-day bleed |
| dream_log (all three, 79%) | syn + sem + prag | Speculative prose is stylistically varied; no single band dominates, all contribute marginal SNR |
| critical_analysis (sem, 59%) | semantic | Critique vocabulary is largely semantic; syntactic and pragmatic add noise for this task |
| static_analysis (syn, 43%) | syntactic | Confused with other code-analysis layers regardless of band; syntactic provides the best partial separation |

### static_analysis confusion

`static_analysis` tops the within-layer ratio (3.4×) but scores worst in the cross-corpus pool
(42.5% top-1).  The reason: static, code reading, dependency, and architectural analysis all
discuss the same source files.  Their BDP signatures share structural features that overwhelm the
per-task differences.  Syntactic weights are the best available separator, but the confusion floor
is ~57%.  Mitigation options: expand the item set from 8 to 16+ files to reduce per-item
signature overlap; or add a content-type discriminator at the retrieval layer.
